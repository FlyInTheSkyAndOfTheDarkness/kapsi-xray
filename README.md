# Kaspi X-Ray

Веб-дашборд аналитики товаров и юнит-экономики магазина **Kaspi.kz** — в стиле
внешних сервисов аналитики маркетплейса (аналог PriceFeed / Kaspi Analytics),
но под собственным брендом **Kaspi X-Ray**.

Трёхъязычный интерфейс: **Русский / Қазақша / English** (переключатель в шапке).

Полноценный SaaS для продавца: **аккаунты (регистрация/вход)**, подключение своего
магазина, юнит-экономика по себестоимости, **отслеживание конкурентов** с серверной
историей и авто-обновлением. Фронт (React/Vite) + бэкенд (Node/Express) с локальной БД.

> Оценки продаж — по публичным данным Kaspi. Не аффилировано с Kaspi.kz.

## Запуск (два процесса)

```bash
# 1) бэкенд (порт 8787): прокси Kaspi, аккаунты, БД, планировщик
cd server && npm install && npm start

# 2) фронтенд (порт 5175): проксирует /api → :8787 и /kaspi → kaspi.kz
npm install && npm run dev
```

Открыть http://localhost:5175 → зарегистрироваться → «Подключить магазин».

## Деплой (прод, один процесс)

В проде бэкенд отдаёт собранный фронт (`dist/`) + `/api` + прокси `/kaspi` на одном порту
(`process.env.PORT`, по умолчанию 8787).

**Docker:**
```bash
docker build -t kaspi-xray .
docker run -p 8787:8787 -v $(pwd)/data:/app/server/data kaspi-xray
# открыть http://localhost:8787
```
Том на `/app/server/data` сохраняет БД (аккаунты, магазины, история, алерты) между рестартами.

**Render / Railway / любой Node-хостинг:**
- Build command: `npm install && npm run build && cd server && npm install`
- Start command: `node server/index.js`
- Переменные: `PORT` (задаёт платформа), опц. `JWT_SECRET` (иначе генерируется в `server/data/secret.txt`),
  `POLL_HOURS` (частота опроса конкурентов, по умолч. 6).

> Секреты и БД (`server/data/`) в `.gitignore` — в репозиторий не попадают.

## Что внутри

| Раздел | Что показывает |
|---|---|
| **Обзор магазина** | По **подключённому магазину** (реальный каталог Kaspi): выручка/прибыль/продажи (оценка), Топ-5 по выручке, структура расходов (по себестоимости), выручка по категориям, убыточные SKU. Без магазина — предложение подключить |
| **Товары** | Реальный каталог вашего магазина: цена, **ввод себестоимости**, продажи, выручка, маржа и прибыль (оценка); поиск, фильтр убыточных, X-Ray по товару, CSV |
| **Юнит-экономика** | Выбор реального товара → водопад «как формируется прибыль»: цена → закупка, комиссия Kaspi, доставка, налог, упаковка, возвраты → чистая прибыль |
| **ABC-анализ** | Классификация товаров магазина по вкладу в выручку (Парето 80/15/5), кривая Парето, таблица A/B/C |
| **Аналитика товара (X-Ray)** | **Живые данные Kaspi**: введите SKU / ссылку / название любого товара → оценка продаж и выручки, график динамики, все продавцы и их цены, кто выигрывает витрину, рейтинг, распределение оценок, история наблюдений, калибровка |
| **Подключить магазин** | Продавец подключает **свой магазин** (per-user, на бэкенде) → каталог, оценка выручки/продаж, **ввод себестоимости → реальная маржа и прибыль** по каждому товару, слот для API-токена кабинета, CSV |
| **Конкуренты** | **Серверное отслеживание** товаров конкурентов: цена, кто выигрывает витрину, продавцы, оценка продаж, история и авто-обновление по расписанию (доступно с любого устройства) |
| **Уведомления** | Колокольчик в шапке: **алерты при изменении цены конкурента** (↑/↓ с %), смене победителя витрины и числа продавцов. Формируются на бэкенде при каждом опросе; клик → X-Ray товара |
| **Аналитика рынка** | Оборот, продажи и число продавцов по категориям и ТОП-брендам Kaspi + индекс возможности (оборот на продавца) |
| **Калькулятор прибыли** | Живой расчёт чистой прибыли, маржи, ROI, точки безубыточности и рекомендуемой цены под целевую маржу |
| **Настройки** | Город доставки + редактируемые коэффициенты «отзыв → заказ» по категориям |

### Аналитика товара — реальные данные Kaspi

Раздел **«Аналитика товара»** работает с публичными эндпоинтами Kaspi.kz
(поиск, продавцы/цены, отзывы). Kaspi отдаёт их только server-side, поэтому в
дев-режиме запросы идут через **прокси Vite** (`/kaspi/*` → `https://kaspi.kz/*`,
см. `vite.config.js`) — так обходится CORS и подставляются нужные заголовки.

- Ввод: SKU, ссылка на товар (`.../p/...-<id>/`) или просто название.
- Deep-link: `/xray?q=<sku|url|название>` — сразу запускает анализ (ссылкой можно делиться).
- **График динамики продаж** с периодами 7 / 14 / 30 / 90 дней и «по месяцам» — строится
  из реальных дат отзывов Kaspi (продажи за день/месяц = отзывы в этот период × коэффициент).
  Переключатель **штуки / выручка ₸** и **кумулятивная линия** (нарастающим итогом).
  Для очень популярных товаров дальние периоды могут быть частичными (помечается) —
  API отдаёт ограниченный объём истории.
- **Коэффициент «отзыв → заказ» зависит от категории** (электроника ×9, спорт ×13,
  дом ×16, красота ×22 и т.д.) — определяется по названию и категории товара
  (`resolveMultiplier` в `src/lib/salesEstimate.js`). Люди оценивают разные категории
  с разной частотой, поэтому оценка продаж точнее, чем при едином коэффициенте.
- Различаем **отзывы** (COMMENT, как на карточке Kaspi) и **оценки** (ALL, из них рейтинг).
- Deep-link параметры графика: `?period=d90&metric=revenue&cum=1` (+ `&watch=1` — сразу добавить в отслеживание).
- **Выбор города** (шапка) — продавцы, цены и доставка запрашиваются по выбранному городу.
- **История наблюдений**: при каждом открытии товара сохраняется снапшот (цена, продавцы,
  оценка продаж) в localStorage — со временем накапливается **реальная** история цены/продавцов.
- **Калибровка**: на карточке товара введите известные реальные продажи/мес — коэффициент
  для этой категории подстроится (или задайте вручную в Настройках).
- **CSV-экспорт** есть на страницах Товары, Аналитика рынка, Аналитика товара (продавцы,
  история) и Отслеживание.

### Подключение магазина

Раздел **«Подключить магазин»** (`/connect`) достаёт **публичный каталог** продавца:
- Ввод — ссылка на любой товар из магазина (в URL есть `m=<id>`) или ID продавца.
- Каталог тянется через фильтр `q=:allMerchants:<merchantId>` (пагинация, до ~96 товаров),
  название/рейтинг магазина — из offers первого товара (`getMerchantProducts`,
  `getMerchantInfo` в `src/data/kaspiApi.js`).
- Продажи/выручка по каждому товару — **грубая оценка** по отзывам (без лишних запросов);
  для точной оценки — кнопка **X-Ray** у товара.
- Подключённый магазин хранится в localStorage, отражается в шапке и сайдбаре. Deep-link:
  `/connect?m=<merchantId>`.
- **Приватные данные** (реальные заказы, себестоимость, прибыль) — это кабинет продавца
  Kaspi: нужен API-токен и бэкенд для его безопасного хранения (следующий шаг, не фронт).

## Бэкенд (`server/`)

Node/Express + локальная JSON-БД (`server/data/db.json`), без нативных зависимостей.

- **Аккаунты**: `POST /api/auth/register|login`, JWT (30 дней), пароли — bcrypt (`auth.js`).
- **Магазины** (per-user): `POST /api/stores/connect`, `GET /api/stores/:id` (каталог +
  оценки + прибыль по COGS), `PUT /api/stores/:id/cogs`, `POST /api/stores/:id/token`,
  `GET /api/stores/:id/orders` (реальные заказы — при наличии токена кабинета).
- **Конкуренты**: `POST /api/competitors` (начать отслеживание + первый снапшот),
  `GET /api/competitors` (+ Δ цены), `GET /api/competitors/:id/history`, `POST /api/competitors/poll`.
- **Уведомления/алерты** (`alerts.js`, `routes-alerts.js`): при опросе сравниваем свежий
  снапшот с базовой линией конкурента → создаём алерт при изменении цены (≥0.5%), смене
  победителя витрины или числа продавцов (≥2). `GET /api/alerts` (+ unread), `POST /api/alerts/read`,
  `DELETE /api/alerts`. Фронт опрашивает раз в 60с; колокольчик в шапке. (Тестовый эндпоинт
  `/api/_dev/nudge/:cid` включается через `KX_DEV=1` — только для проверки, в проде не нужен.)
- **Планировщик** (`scheduler.js`): каждые `POLL_HOURS` (по умолч. 6) снимает снапшот
  цены/продавцов/оценки по всем отслеживаемым товарам — история растёт без открытого браузера.
- **Kaspi-клиент** (`kaspi.js`): серверные вызовы Kaspi (поиск, offers, reviews, каталог
  магазина) + сквозной прокси `/kaspi/*` (drop-in замена дев-прокси Vite для прода).
- **Токен кабинета** хранится только на сервере; в браузер не попадает. Пока токена нет —
  продажи/прибыль оцениваются по отзывам + введённой себестоимости.

Оценка продаж переиспользует те же `src/lib/salesEstimate.js` / `economics.js`, что и фронт.

### Хранение данных (клиент)

Настройки (город, коэффициенты), язык и локальные снапшоты X-Ray хранятся в **localStorage**
(`src/lib/store.js`, `src/state/AppState.jsx`). Аккаунты, магазины, себестоимость и конкуренты —
на бэкенде (доступны с любого устройства).
- **Продажи — это оценка** по динамике отзывов (≈1 отзыв на 14 заказов): Kaspi не
  публикует точные продажи, как и все внешние сервисы аналитики. Модель и коэффициент —
  в `src/lib/salesEstimate.js`; достоверность оценки показывается в интерфейсе.
- Если Kaspi недоступен (антибот / прод без прокси) — раздел показывает демо-данные
  с пометкой, интерфейс не ломается.

> **Для продакшена:** тот же прокси нужно поднять как небольшой бэкенд / edge-функцию
> (Kaspi нельзя вызывать напрямую из браузера). Вся сетевая логика — в
> `src/data/kaspiApi.js`, достаточно поменять префикс `/kaspi` на адрес вашего прокси.

## Стек

- **React 18 + Vite 5**, React Router
- Собственный лёгкий движок i18n (`src/i18n`)
- Экономика и форматтеры — чистый JS (`src/lib`), детерминированные мок-данные (`src/data`)
- Графики — самописные SVG-компоненты (`src/components/Charts.jsx`); палитра проверена
  на цветовую доступность (CVD)

## Структура

```
src/
  main.jsx            точка входа, подключение стилей
  App.jsx             маршруты
  i18n/               движок i18n + словари RU/KK/EN
  lib/                economics.js (юнит-экономика, ABC), format.js (₸, %)
  data/               mockData.js — детерминированный каталог + агрегаты магазина
  components/         Shell (сайдбар/шапка), ui (карточки/KPI), Charts (SVG)
  pages/              Overview, Products, UnitEconomics, ABCAnalysis, Market, Calculator
  styles/             theme.css (токены), global/shell/pages/charts.css
```

Все данные согласованы из одного источника (`MONTHLY` в `data/mockData.js`): KPI
магазина, дневной график и помесячная прибыль товаров считаются из одного каталога.
Чтобы подключить реальные данные Kaspi — замените `src/data/mockData.js` на слой
загрузки из API, сохранив те же поля.
