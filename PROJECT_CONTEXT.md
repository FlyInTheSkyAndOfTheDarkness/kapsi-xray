## 3. Что это за продукт

Kaspi X-Ray — React/Node.js SaaS для продавцов Kaspi:

- регистрация, вход и управление доступами;
- подключение Kaspi-магазина по merchant ID и отдельно по API-токену продавца;
- каталог товаров, себестоимость, цена, остаток, упаковка, логистика и маржа;
- обзор магазина, ABC-анализ и юнит-экономика;
- публичная аналитика товаров Kaspi и прогноз продаж;
- отслеживание конкурентов и демпинг-бот;
- импорт товара из Taobao, Tmall и 1688;
- перевод китайских характеристик;
- загрузка и AI-перевод текста на фотографиях;
- подготовка карточки Kaspi и публикация;
- предзаказы через XML price-list feed;
- админская страница пользователей и их показателей.

Важно: продажи по публичным данным Kaspi являются оценкой, обычно на основании
отзывов. Точные заказы доступны только через API-токен кабинета продавца.

## 10. Подключение Kaspi-магазина

Есть два разных режима, их нельзя смешивать:

1. Публичное подключение по merchant ID:
   - загружает публичный каталог;
   - позволяет оценивать продажи, цены и конкурентов;
   - не даёт управлять кабинетом.

2. API-токен продавца:
   - хранится только на backend;
   - нужен для заказов, справочника категорий, обязательных характеристик и
     отправки карточек через merchant API.

Основные endpoints находятся в `server/routes-stores.js`:

```text
POST   /api/stores/connect
GET    /api/stores
GET    /api/stores/:id
DELETE /api/stores/:id
POST   /api/stores/:id/token
GET    /api/stores/:id/orders
GET    /api/stores/:id/classification/categories
GET    /api/stores/:id/classification/attributes
POST   /api/stores/:id/import-products
GET    /api/stores/:id/imports/:code
GET    /api/stores/:id/preorder-feed
```

Кнопка отключения магазина должна вызывать `DELETE /api/stores/:id`.

## 11. Taobao / Tmall / 1688

Главная страница: `src/pages/TaobaoImport.jsx`.

Поддерживаются:

- публичная ссылка товара;
- Taobao/Tmall URL с item ID;
- 1688 URL вида `https://detail.1688.com/offer/<id>.html`;
- импорт через браузерную закладку, когда marketplace показывает товар только
  после входа или блокирует серверный запрос.

Парсер:

- определяет marketplace;
- извлекает ID, название, цену, изображения и характеристики;
- переводит китайский текст;
- конвертирует CNY в KZT;
- добавляет доставку и наценку;
- создаёт редактируемый черновик предзаказа.

Taobao и 1688 часто отдают серверу страницу логина/защиты. Это нормальное внешнее
ограничение. В таком случае используется режим «Через браузер»:

1. На странице `/taobao` создать/скопировать актуальную закладку.
2. Открыть товар в авторизованном Chrome.
3. Нажать закладку `Send to Kaspi X-Ray`.
4. Закладка передаёт данные открытой страницы в `/api/taobao/browser-import`.

После изменений bookmarklet пользователь должен удалить старую закладку и создать
новую, иначе Chrome продолжит выполнять старый JavaScript.

## 12. Предзаказы и публикация в Kaspi

Список: `/taobao/preorders`.

Карточка: `/taobao/preorders/:id`.

Карточка предзаказа позволяет:

- редактировать SKU, бренд, название, описание и категорию;
- выбирать официальный код категории Kaspi (`Master - ...`);
- загружать/удалять/менять порядок фотографий;
- переводить китайский текст на изображении на русский или казахский;
- открывать оригинал и перевод в большом окне;
- задавать цену, остаток, склад и срок доставки предзаказа;
- загружать справочник обязательных характеристик Kaspi;
- заполнять характеристики вручную или кнопкой AI;
- отправлять и повторно публиковать товар;
- удалять локальный черновик.

Публикация состоит из двух связанных частей:

1. Карточка/контент отправляется через Kaspi merchant product import API.
2. Цена, остаток, склад и `preOrder` попадают в XML price-list feed.

Поэтому успешный ответ API ещё не означает, что предложение уже видно в магазине.
Нужно:

- один раз вставить URL XML-feed в кабинете Kaspi:
  `Товары -> Загрузить прайс-лист -> Автоматическая загрузка`;
- оставить логин и пароль XML-feed пустыми;
- дождаться, пока Kaspi запросит feed и обработает карточку;
- затем синхронизировать статус на странице предзаказов.

Публичный XML endpoint:

```text
/api/stores/preorder-feed/:key.xml
```

URL feed уникален для магазина. Не публиковать его в документации или логах как
обычную публичную ссылку: ключ даёт доступ на чтение прайс-листа.

Товар попадает в XML только когда заполнены:

- SKU;
- название/model;
- бренд;
- цена больше нуля;
- минимум один склад;
- минимум одна фотография;
- срок предзаказа в допустимом диапазоне.

Товар с нулевым остатком или снятый с продажи из файла **не выбрасывается**: он
уходит с `available="no"` и `stockCount="0"`. Если его просто не упомянуть, Kaspi
оставит прежнюю цену и продолжит продавать.

Текущий максимальный срок задаётся `MAX_PREORDER_DAYS` в
`server/taobao-product.js`.

### Правила Kaspi, зашитые в код

Из документации (`guide.kaspi.kz/.../price_list`, статьи `q2962` и `q3347`):

1. **«Не редактируйте карточку товара, иначе покупатели не смогут оформить на него
   предзаказ. Используйте для этого прайс-лист».** Карточка уходит в import API
   ровно один раз: `cardLocked()` в `server/routes-taobao.js` блокирует повторную
   отправку. Демпинг-бот и кнопка публикации цены для предзаказных SKU пишут цену
   в черновик (`server/preorder-link.js`), а её забирает feed. Разблокировка —
   только явная, `POST /api/taobao/preorders/:id/unlock-card`.
2. **«Артикул может содержать цифры и латинские буквы, максимум 20 символов».**
   `kaspiSku()` в `server/taobao-product.js` нормализует SKU в единственном месте,
   через которое проходит каждый черновик, — иначе Kaspi не свяжет offer с карточкой.
3. **«Напишите "Без бренда"»** для товаров, которым не нужно разрешение на торговлю.
   Константа `NO_BRAND`; подставляется автоматически, пустой бренд Kaspi не принимает.
4. **«Товары из файла, которых нет в продаже, перейдут в Нераспознанные товары →
   Без привязки».** Это ручной шаг; статус `awaiting_link` показывает его в списке
   предзаказов.
5. **«Если вы ранее загружали или добавляли товар вручную, его нужно добавить
   в прайс-лист, иначе он будет снят с продажи».** Прайс-лист замещает ассортимент
   целиком.

### Склады в прайс-листе

Карта точек выдачи магазина хранится в `stores.priceListWarehouses` как
`[{ id, available }]` и настраивается через `PUT /api/stores/:id/preorder-feed`.
Точка с `available: false` остаётся в XML с `available="no"` — только так Kaspi
перестаёт с неё продавать. Если карта не задана, берутся склады самого товара.

### Стадии товара

`draft` → `card_sent` → `in_feed` → `awaiting_link` → `on_sale`, плюс `blocked`.
Считаются в `preorderStage()` (`server/routes-taobao.js`) из статуса импорта,
состояния прайс-листа и времени последней загрузки со стороны Kaspi.

### Тесты

`cd server && npm test` — `node --test` на временном каталоге данных
(`KX_DATA_DIR`), боевая `server/data/db.json` не затрагивается.

## 13. Категории и обязательные характеристики

Для публикации нужен **официальный код категории Kaspi**, обычно вида:

```text
Master - Headphones
Master - Bicycles
```

Не нужно отправлять произвольное русское название категории как код.

После выбора категории backend запрашивает официальный справочник атрибутов:

```text
GET /api/stores/:id/classification/attributes?category=Master%20-%20...
```

В Kaspi должны уходить только официальные коды из этого справочника. Сырые
характеристики Taobao/1688 (`Категория`, `Прямо с завода` и т.п.) нельзя отправлять
как Kaspi-коды.

Недавнее исправление:

- технический код характеристики сохраняется **точно** как в справочнике Kaspi,
  включая обязательные разделители `*`;
- пользователю отдельно показывается русское название поля, технический код не
  используется как видимая подпись;
- для `enum` загружаются разрешённые значения через
  `/classification/attribute/values`;
- перед отправкой атрибуты сверяются с официальным справочником категории;
- старые коды без `*` автоматически сопоставляются с точными кодами и дубли
  объединяются;
- сырьевые поля Taobao/1688, которых нет в категории Kaspi, удаляются из списка
  отправки;
- ошибки Kaspi вида `attributes[n].code does not match regex` разбираются;
- карточка предзаказа подсвечивает конкретную проблемную строку;
- есть шпаргалка и кнопка автоматического исправления списка.

Связанные файлы:

```text
server/routes-taobao.js
server/routes-stores.js
server/ai-attributes.js
src/pages/TaobaoPreorderDetail.jsx
src/styles/pages.css
src/i18n/translations.js
```

AI при заполнении атрибутов должен использовать данные карточки и фотографии, но
не придумывать обязательные значения без подтверждения. Для enum-поля результат
должен быть одним из значений, разрешённых справочником Kaspi.

## 14. AI-перевод фотографий

Настройки API доступны пользователю через интерфейс и endpoints:

```text
GET /api/ai/settings
PUT /api/ai/settings
POST /api/ai/images/localize
POST /api/ai/images/discard
```

Поддержаны OpenAI и Gemini. Цель функции: заменить китайский текст русским или
казахским, сохранив товар, композицию и общий вид изображения.

Без API-ключа реальная AI-обработка фотографии невозможна. Интерфейс не должен
показывать фиктивный успешный результат. Ошибка провайдера должна быть понятной,
но API-ключ и полный upstream-ответ нельзя выводить пользователю.

## 15. Статусы импорта

Backend хранит попытки в коллекции `imports`, а товары — в `taobaoProducts`.

UI сводит технические ответы Kaspi к понятным состояниям:

- черновик;
- в процессе;
- опубликован;
- отклонён/ошибка;
- отменён.

Технические статусы Kaspi могут включать `UPLOADED`, `FINISHED`, `FAILED` и
item-level state. Источник истины — результат endpoints import status/result,
а не сам факт, что запрос на импорт получил HTTP 200.

При отклонении пользователь должен видеть:

- точную причину;
- рекомендацию;
- проблемную характеристику, если её удалось определить;
- кнопку перехода к полю;
- повторную публикацию после исправления.

- показывать данные помесячно;
- прогнозировать будущие 6 месяцев;
- учитывать сезонность соответствующих месяцев прошлого года;
- не занижать октябрь-декабрь, если в прошлом году там был высокий сезон.

Нельзя называть оценочный прогноз точными продажами. В интерфейсе должны быть
пометки о качестве данных и источнике оценки.

## 17. Деплой

Файлы:

```text
Dockerfile
deploy/docker-compose.yml
deploy/kaspi-xray.env.example
deploy/nginx/kaspi-xray.conf
deploy/README.md
```

Контейнер:

- собирает React в `/app/dist`;
- запускает `node server/index.js`;
- слушает порт 8787;
- сохраняет `/app/server/data` в Docker volume;
- nginx проксирует HTTPS-субдомен на `127.0.0.1:8787`.

Обычное обновление сервера, только после прямой команды пользователя:

```bash
cd /opt/kaspi-xray/deploy
docker compose up -d --build
docker compose ps
curl http://127.0.0.1:8787/api/health
```

После деплоя обязательно проверить не только health endpoint, но и:

- загрузку frontend;
- вход;
- подключение магазина;
- `/kaspi` proxy;
- карточку предзаказа;
- публичную XML-feed ссылку;
- сохранность Docker volume.

## 18. Проверка перед завершением изменений

Минимальный набор:

```bash
npm run build
node --check server/index.js
node --check <изменённый backend-файл>
curl http://127.0.0.1:8787/api/health
```

Для UI:

- открыть локальный URL;
- проверить browser console;
- проверить desktop и узкое окно;
- убедиться, что Material Symbols показываются иконками, а не словами
  `menu`, `shopping_bag`, `location_on` и т.п.;


Он нужен, потому что внешний шрифт иконок может не загрузиться.

## 20. Ближайшая зона проверки

Последняя реализованная задача — русифицировать обязательные характеристики,
сохранив точные коды Kaspi, и сделать ошибки понятными в карточке предзаказа.
Следующему AI стоит проверить реальным локальным сценарием:

1. Открыть отклонённый предзаказ.
2. Убедиться, что `attributes[n].code` преобразуется в конкретную подсвеченную строку.
3. Нажать «К характеристикам».
4. Удалить неизвестные поля либо выбрать официальные поля из справочника.
5. Убедиться, что видимая подпись русская, а технический код содержит исходные
   разделители `*`.
6. Заполнить enum только разрешёнными значениями из Kaspi.
7. Повторно опубликовать.
8. Проверить фактический ответ Kaspi и XML-feed, а не только локальный статус.
